# Email architecture and future DNS work

## Two separate systems

Proton provides the human mailbox for `ray@utopiahomes.com`; Vercel does not host business inboxes. Role-specific addresses such as `info@utopiahomes.com` and `owners@utopiahomes.com` are intentionally deferred.

Transactional email is generated by website forms. V1 sends through Proton SMTP submission behind the provider-neutral `EmailProvider` interface. The Resend HTTPS adapter remains available but inactive, so changing providers does not require form, storage, or retry changes.

## Server-only variables

- `EMAIL_PROVIDER=proton`
- `PROTON_SMTP_USER` — copy the username Proton generates for the selected custom-domain address
- `PROTON_SMTP_TOKEN` — one-time generated SMTP token; never use the normal Proton password
- `PROTON_SMTP_FROM=Utopia Homes <ray@utopiahomes.com>`
- `LEAD_NOTIFICATION_EMAIL` — temporary centralized destination; set to `ray@utopiahomes.com`
- `SEND_CONFIRMATION_EMAILS`
- `NOTIFICATION_EMAIL_ENABLED` — set `false` to pause delivery and retries without pausing lead capture
- `CRON_SECRET` — random 16+ character secret used by Vercel to authenticate the retry route

## Durable delivery operations

Internal lead notifications are stored in `public.notification_outbox`. The application tries a new item immediately; Vercel Hobby also calls `/api/cron/notifications` once daily at 12:00 UTC as a safety net. The route requires `Authorization: Bearer <CRON_SECRET>`. A notification is attempted at most six times with bounded exponential backoff, then marked `dead` for human attention. The outbox's lease and sent-state checks protect ordinary retries and concurrent workers from duplicate delivery. SMTP does not offer the API-level idempotency key supported by Resend, so an indeterminate network failure after Proton accepts a message can still produce a rare duplicate on retry. Optional submitter confirmations remain best-effort and are not part of the internal-notification outbox.

Current routing is deliberately simple: owner leads, contact requests, membership signups, and Utopia Interiors inquiries all use `LEAD_NOTIFICATION_EMAIL`. The authenticated sender is `PROTON_SMTP_FROM`. Internal notifications set `Reply-To` to the visitor's submitted email, so replying reaches the visitor rather than the Utopia sender.

## One-time Proton setup

1. In Proton Mail, open **Settings → All settings → IMAP/SMTP → SMTP tokens**.
2. Generate a token named `Utopia Homes Vercel Production`, select the active `ray@utopiahomes.com` custom-domain address, and confirm with the normal Proton account password.
3. Copy both values Proton displays: use the generated username as `PROTON_SMTP_USER` and the one-time password as `PROTON_SMTP_TOKEN`. The token cannot be viewed again after the dialog closes.
4. For stronger environment separation, generate a second token named `Utopia Homes Vercel Preview` and use it only for Vercel Preview.
5. In Vercel, add the variables listed above as encrypted server-side values. Redeploy only after all values are present.

The adapter connects to `smtp.protonmail.ch:587`, requires STARTTLS, and uses bounded DNS, connection, greeting, and socket timeouts. SMTP traffic logging is disabled. Stored errors are deliberately sanitized to a category and numeric SMTP response code; credentials and message contents are not logged.

Inspect the queue in Supabase SQL Editor:

```sql
select id, submission_id, kind, recipient, status, attempt_count,
       next_attempt_at, last_attempt_at, sent_at, provider_message_id,
       last_error, created_at, updated_at
from public.notification_outbox
order by created_at desc;
```

Manually retry a known failed/dead item only after checking Proton's Sent folder if the prior result was uncertain:

```sql
update public.notification_outbox
set status = 'pending', attempt_count = 0, next_attempt_at = now(),
    locked_until = null, lease_token = null, updated_at = now()
where id = '<notification-uuid>'
  and status in ('failed', 'dead');
```

Set `NOTIFICATION_EMAIL_ENABLED=false` in Vercel and redeploy to stop immediate sends and cron retries while Supabase continues capturing form submissions and pending outbox records. Re-enable it and redeploy to drain the queue.

No DNS changes are part of this integration. Proton SMTP submission uses the already configured Proton custom-domain sender. Preview should initially send only controlled tests; confirmations should remain disabled until delivery and Reply-To behavior are verified.
