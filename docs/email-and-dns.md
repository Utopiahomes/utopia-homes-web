# Email architecture and future DNS work

## Two separate systems

Business mailbox hosting provides human inboxes such as `ray@utopiahomes.com`, `info@utopiahomes.com`, and `owners@utopiahomes.com`. Choose Microsoft 365, Google Workspace, or another mailbox provider separately; Vercel does not host these inboxes.

Transactional email is generated by website forms. V1 is prepared for Resend through its HTTPS API. The website sender should use a verified subdomain such as `notifications@updates.utopiahomes.com` so transactional reputation and records are separated from human mailbox hosting.

## Server-only variables

- `RESEND_API_KEY`
- `RESEND_FROM_EMAIL`
- `UTOPIA_NOTIFICATION_EMAIL`
- `UTOPIA_OWNERS_EMAIL`
- `SEND_CONFIRMATION_EMAILS`
- `NOTIFICATION_EMAIL_ENABLED` — set `false` to pause delivery and retries without pausing lead capture
- `CRON_SECRET` — random 16+ character secret used by Vercel to authenticate the retry route

## Durable delivery operations

Internal lead notifications are stored in `public.notification_outbox`. The application tries a new item immediately; Vercel also calls `/api/cron/notifications` every five minutes. The route requires `Authorization: Bearer <CRON_SECRET>`. A notification is attempted at most six times with bounded exponential backoff, then marked `dead` for human attention. Resend receives a stable idempotency key on every attempt. Optional submitter confirmations remain best-effort and are not part of the internal-notification outbox.

Inspect the queue in Supabase SQL Editor:

```sql
select id, submission_id, kind, recipient, status, attempt_count,
       next_attempt_at, last_attempt_at, sent_at, provider_message_id,
       last_error, created_at, updated_at
from public.notification_outbox
order by created_at desc;
```

Manually retry a known failed/dead item only after checking its Resend activity if the prior result was uncertain:

```sql
update public.notification_outbox
set status = 'pending', attempt_count = 0, next_attempt_at = now(),
    locked_until = null, lease_token = null, updated_at = now()
where id = '<notification-uuid>'
  and status in ('failed', 'dead');
```

Set `NOTIFICATION_EMAIL_ENABLED=false` in Vercel and redeploy to stop immediate sends and cron retries while Supabase continues capturing form submissions and pending outbox records. Re-enable it and redeploy to drain the queue.

## DNS records to add later—not now

After creating the Resend account and adding the sending domain, copy the exact DKIM and SPF records Resend supplies into the active Wix/GoDaddy DNS zone. Add DMARC after reviewing mailbox and transactional senders. Do not guess record values, and do not replace business-mail MX records when adding transactional records.

Preview should initially send only to a controlled test address. Production recipients and confirmations should be enabled only after domain verification and deliverability testing.
